The standalone doublegate-sdk validates declarative manifests and runs bounded literal checks offline. Its output is evidence for a review, not permission to install, publish or execute an artifact.

Start from source

Python 3.11+. The file loader supports Linux/WSL and requires POSIX operations; native Windows loading is unsupported. The core has no runtime dependencies or service installation.

Clone the public SDK repository, create a Python environment and follow the versioned quickstart for installation and execution commands.

Development snapshot 0.1.0.dev0. Source and build artifacts are distributed through GitHub; there is no PyPI package or stable release. Use the source checkout, not a package index.

Architecture

Own the memory path.
Keep sources intact.

DoubleGate is designed as a memory provider for the corpus routed through it: admission, storage and eligible retrieval. It is not an SDK wrapper that adds review to an arbitrary existing store.

Repositories, tickets and policy documents remain systems of record. Contributions reference their sources; a signed decision records who accepted a revision and why. A hash or signature establishes a binding, not the truth of the content.

Memories hold reusable claims; skills can carry executable instructions; records preserve events. Their risks differ. Review of a skill is separate from permission to execute it.

Plan the deployment, not just the import

Local client

Python and local SQLite storage. Decide which agent memory path will use it and preserve a rollback route to your existing workflow.

Organization design

PostgreSQL is the intended decision authority; Delta supports rebuildable projections. Authenticated HTTP crosses deployments; local adapters stay local.

Inference and operations

Hosted reviewers receive reviewed content. Local models keep inference on your infrastructure. Budget for storage, queue monitoring, backups and restore tests.

Customer-controlled and managed operation are proposed deployment options, not a live hosted SDK service. Operating responsibilities · Identity, retention and governance requirements.

Measure the cost of useful knowledge

Review adds model cost, time before publication and operational work. Measure retrieval relevance and latency alongside current eligibility checks; a fast wrong answer is not a useful result.

Access grants, retention and erasure are separate deployment requirements. Test recovery, expiry and withdrawal, including downstream copies and backups, rather than equating a local deletion with complete erasure.

Historical token measurements are available in the evidence. They are not a budget guarantee for the selected two-stage review or your workload.

Make the integration earn its place

Use a non-sensitive, team-owned set of conventions or runbooks. Compare correct, applicable task completion with your existing storage and review workflow using the same source access and review budget.

Include harmful admissions, useful contributions rejected, stale revisions, unauthorized consumers, recovery and time to an effective correction. Record failures, reviewer effort and total cost. SDK fixture success proves none of those deployment outcomes.

Release sequence

Current source and API artifacts support development evaluation. The provider adoption release is the first planned agent integration; the complete reviewed, shared system follows in stages.

  1. R1Ledger and quarantineSigned journal, isolated stores and envelope format establish the integrity foundation.
  2. R2Provider adoption — {first_release}Storage, search, importer and the first agent-tool client. Review follows; this date does not promise the complete shared system.
  3. R3Two-stage reviewA non-author AI assesses trust from 0–100. A second authorized AI or human, distinct from author and assessor, issues binary APPROVE or REJECT for the exact revision and use. No second score; human participation depends on policy. Evaluate calibration and errors.
  4. R4Shared organizational controlsMulti-deployment synchronization, contributor and team attribution, current read permissions, scoped publication, withdrawal and erasure tooling. Deployment authorities are separate from the two review stages.
  5. R5Skills, daily review and CommonsSkill revision proposals, a bounded review digest, contradiction handling and the reviewed public library. Public contribution requires explicit publishing rights.

Only the adoption release is dated. Later dates depend on the preceding releases and their acceptance evidence.
